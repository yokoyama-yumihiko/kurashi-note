# くらしノート Coding Rules

## 1. Basic Policy

くらしノートでは、読みやすく、安全で、
将来修正しやすいコードを優先します。

複雑な実装よりも、
シンプルで理解できる実装を選択します。

## 2. Before Coding

コードを書く前に必ず、

1. 目的を確認する
2. 必要な機能を整理する
3. 既存コードへの影響を確認する
4. 実装方法を決める
5. バックアップ・Gitの状態を確認する

という順序で進めます。

## 3. Coding Principles

- 1つの機能を小さく作る
- 分かりやすい名前を使う
- 不要なコードを残さない
- 同じ処理を不必要に重複させない
- コメントは「なぜ」を中心に書く
- APIキーやパスワードをコードに書かない
- AIが生成したコードも必ず確認する

## 4. Testing

変更後は必ず動作確認します。

問題が発生した場合は、

Problem
→ Cause
→ Fix
→ Test
→ Review

の順で原因を確認します。

## 5. Git Rules

基本単位は、

Edit
→ Save
→ Test
→ Commit
→ Push

とします。

コミットメッセージは、
「何を変更したのか」が分かる短い文章にします。

## 6. AI Development Rules

ChatGPT・Claude等のAIを開発支援に利用できます。

ただし、

- AIのコードを無条件で採用しない
- 実行前に内容を確認する
- 大規模変更は分割する
- エラーを隠して先へ進まない
- 不明なコマンドは意味を確認してから実行する

ことを原則とします。

## 7. Security

以下の情報はGitHubへ公開しません。

- Password
- API Key
- Access Token
- 個人情報
- 非公開資料
- 認証情報

秘密情報は環境変数など、
適切な方法で管理します。
