# 朝のニュース 下書きの作り方（AI向け手順）

毎朝6時に、この手順で「今朝のニュース」の下書きを作る。公開は本人が確認してから。
Macのターミナルでもクラウド（スマホ）でも同じ手順。作業の最初に `git pull`（CLAUDE.md 13章）。
利用枠（トークン）を使いすぎないため、ニュース探しはプログラムに任せ、AIは選ぶ・短く書くだけにする。

## まずはこちら：ChatGPT の朝のブリーフを取り込む（Claude の利用枠をいちばん使わない）

ChatGPT が毎朝6時に、ニュース・イベント・グルメ・制度を調べ、最後に「CLAUDE HANDOFF｜くらしノート」の jsonl ブロックを付ける（ChatGPT 側の指示文はリポジトリ外で管理）。

1. 本人が貼り付けたブロックを `data/_candidates/YYYY-MM-DD.handoff.txt` に保存する（Claude は中身を読み直さない）
2. `python3 tools/import_handoff.py data/_candidates/YYYY-MM-DD.handoff.txt` を実行。リンクを1件ずつ開いて確かめ、合わないものは捨てる。ニュース→ data/news、イベント・グルメ→ data/town.json、制度→ .seido.jsonl（DBには入れない）
3. **検証（2026-10-26〜、下の「公開前の検証」）**：`python3 tools/verify.py run` → `python3 tools/verify.py show`。HOLD になったものは、Claude が WebFetch で元ページを照合して本人に示し、本人が確かめたものだけ `release`。それ以外は外す（公開データからは自動で外れている）
   - 前の日に載せた記事・イベント告知だけのニュースは、確認の前に外す（確認の手間を減らす）
4. `keywords` が空なら、ニュースの見出しから3つ入れる
5. **Claude 独自の調査を必ず足す（2026-10-20 本人指示、恒久ルール）**：HANDOFF を取り込んだ日も、次の2つを毎回行い、ChatGPT が拾っていない話題を足す
   - 自前の候補集め：`python3 tools/collect_news.py` を実行し、`.txt` だけを読んで、HANDOFF と重ならないものを選ぶ（市・町・13地区の市民センター。選び方は下の「手順（自前の候補集め）」2〜4）
   - Instagram：下の「Instagram からイベントを集める」（Mac のみ。クラウドからはできないので、その日は「Instagram は未確認」と本人に伝える）
   - 足したものも手順3と同じようにファクトチェックする。何を足したかを本人に一覧で示す
6. 下の手順 5〜7（検証・ページ作成・本人OKで公開）

ChatGPT のブリーフが来ない日は、下の手順（自前の候補集め）だけで作る。

## 手順（自前の候補集め）

1. `python3 tools/collect_news.py` を実行し、`data/_candidates/YYYY-MM-DD.json` と `.txt` を作る（AIは使わない）。最後に情報源ごとの件数が出る：「0件（読めたが該当なし）」と「失敗」は別。失敗が続く情報源は本人に伝える（記録：data/_logs/sources.jsonl）
   - 一覧の日付の「◎」は前日6時〜当日6時の更新。◎を優先して選ぶ
   - 一覧の最後の「編集方針の確認が必要」は、事件・事故・政治などの言葉が当たったもの。住民への具体的な影響・必要な行動があるときだけ選ぶ
2. 候補は **`.txt`（1行1件の短い一覧）だけを読み**、**8〜10本** を選ぶ。JSON は読まない（利用枠の節約）
   - 優先：藤沢市 → 寒川町 → 神奈川県。暮らしに直接関わるもの（申し込み・期限・料金・防災・健康・子育て・交通・事故や個人情報の漏えいなど）を先に
   - 選ばない：イベント告知だけのもの・部署名だけの見出し・職員募集・議員や政党の活動報告・同じ話題の重複（第2報があれば新しい方だけ）
   - 選ばない（編集方針、2026-10-18）：藤沢市・寒川町に直接関係しない局地的な事件・事故・食中毒など。市民の不安を不必要にあおらない・風評被害を防ぐ。ただし具体的な危険が及ぶ情報や行政が対応を求める情報は載せる（あおる言葉を使わず、事実と「何をすればよいか」だけ）。`tools/editorial.py` が候補集め・取り込みで自動的に外し、`build.py --check` が「注意」を出す。掲載しないと決めた記事は `data/excluded.json` に足す（翌日以降も載らない）
   - 茅ヶ崎市の話題は載せない
3. 全国（国政・国の制度）は **2〜3本**、海外は **0〜1本**。候補一覧の「全国」（厚生労働省・デジタル庁・文部科学省・消費者庁・政府広報オンライン・気象庁・国民生活センター）と「海外」（BBCニュース Japan）から選び、足りなければ WebSearch で1〜2回まで。政党・政治家の主張や政局は書かず、決まったこと・始まる制度などの事実だけ。中身を確かめられなければ入れない
4. `data/_candidates/YYYY-MM-DD.picks.json` に、選んだ候補の **番号** と短い文だけを書き、`python3 tools/make_brief.py` で `data/news/YYYY-MM-DD.json` を作る（見出し・URL・出典・日付は番号から自動で入る。形は make_brief.py の説明を参照）
   - 候補にない全国ニュースだけは `extra` に `docs/news-data.md` の形で書く
   - `title`：元の見出しのまま（extra のときだけ書く）
   - `summary`：見出しと説明文（excerpt）に書いてあることだけを、自分の言葉で2文以内。**書いていない数字・日付・名前を足さない**。説明文がなく中身がわからないときだけ、元のページを1回読む（1日5本まで）。それでもわからなければ選ばない
   - `impact`：暮らしにどう関わるかを1文。誰に関係するか・何をすればよいかがわかるように。推測になる場合は「〜の可能性があります」と書く
   - 記事の文章をそのまま写さない（著作権）。評価・意見・政治的な主張を書かない
   - `keywords`：今日の話題を表す言葉を3つ
   - `today_in_history`：出典で確かめられる記念日だけ。確かめられなければ項目ごと入れない
   - **まちのイベント・グルメ**：候補一覧の「## イベント」「## グルメ」から、これから開かれるイベントと新しいお店の話題を picks.json の `town` に書く（形は make_brief.py の説明）。日時・場所は見出しと説明文に書いてあるものだけ。わからなければ元のページを1回読む（ニュースと合わせて1日5本まで）。終わった催しの報告記事・広告・評価（「おいしい」等）は書かない
5. 下の「公開前の検証」の 1〜3（`verify.py run` → `show` → `review`）
6. `python3 tools/build.py` でページを作る（本人の承認待ちの記事も表示される。push の前なので公開はされない）
7. 本人に見せて、OKが出たら `verify.py approve` → `python3 tools/build.py --check` → commit・push（自動公開に切り替えるかは本人が決める）

## 公開前の検証（2026-10-26 本人決定。仕組みは tools/gate.py・tools/verify.py の先頭の説明）

検証は4段階。AI の「確認しました」だけでは進まない。2026-10-27 以降のデータにかかる（それより前のデータはこれまでどおり表示）。

| 段階 | 誰が | 何を |
|---|---|---|
| SOURCE_VERIFIED | verify.py（機械） | 個別ページを開けた・本文を取れた・見出しが合った。取得日時・HTTP・参照URLを記録 |
| FACT_VERIFIED | 機械＋Claude | 要約の金額・人数・日付・期限・時刻・対象条件・場所の根拠を本文から探して記録（機械）→ Claude が根拠の箇所を読んで意味が合うか照合（review） |
| EDITORIAL_APPROVED | 機械＋Claude | 地域性・実用性・政治的中立・風評被害のおそれ。機械の警告（!）を見て、確かめた内容を --note に書く（review） |
| PUBLISH_APPROVED | 本人 | 本人が「OK」と言ったときだけ `approve` を実行 |

1. `python3 tools/verify.py run`：元ページを開き、本文・公開日/更新日・根拠・鮮度・重複・情報源・編集方針を確かめる。
   確かめられないもの（×）は **HOLD** として公開データから外し、`data/_verify/`（公開しない）にだけ残す
   - ニュース：前日6時〜当日6時を優先。それより前は警告、7日より前・日付不明は HOLD
   - イベント：今後30日以内に開かれるもの。終わったもの・30日より先は HOLD
   - 重複：URL・似た見出し・同じイベント・同じ制度・過去14日の掲載。続報（ページの日付が新しい）は消さずに警告で示す
   - 情報源：`data/sources.json` にないドメインは HOLD（本人が確かめてから足す）
   - 政治家・政党・選挙活動は HOLD。事件・事故・感染症は、載せる文に住民の行動（回収・運休・通行止め・注意報など）がなければ HOLD、あれば警告
2. `python3 tools/verify.py show`：要約の各項目と、本文の根拠の箇所（○／×）。**Claude はページ全文ではなくこの根拠の箇所を読んで照合する**
3. `python3 tools/verify.py review D --n 1,2 --fact ok --editorial ok --note "確かめた内容"`。合わなければ `--fact ng --note "理由"`（HOLD になる）。要約を直したら、もう一度 `run`（内容が変わると確認はやり直し）
4. HOLD：`python3 tools/verify.py hold` で理由を見る。Claude が WebFetch（Instagram は Chrome）で元ページを照合して本人に示し、本人が確かめたら `release D --n 3 --note "本人の確認内容"`。載せないなら `drop D --n 3 --reason "..."`（`--exclude` で翌日以降も出さない）
5. 本人OK → `python3 tools/verify.py approve D --all --note "本人の返事"` → `python3 tools/build.py --check`（承認のない記事が1件でもあれば止まる）→ commit・push
   - Mac では push の前に `.git/hooks/pre-push`（tools/hooks/pre-push の写し）が `build.py --check` を自動で通す
   - クラウドでは `data/_verify/` が残らないので、run〜approve を1回の作業の中で行う。フックもないので `build.py --check` を必ず手で実行する

## 文体

- 結論を先に。専門用語は使わないか、括弧で短く説明する
- 学生・子育て世代・高齢者の誰が読んでもわかる言葉で
- 1本は読んで30秒以内に収める

## 地区（自治会）レベルの話題（2026-10-19 本人指示「なるべく地域（自治会）レベルのものも拾う」）
